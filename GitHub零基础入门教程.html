01

GitHub 是什么

先把名词搞清楚，后面就不会晕

GitHub 是全球最大的代码托管平台。你写的代码可以放在它的服务器上，有完整的修改历史，可以随时回退，也能让别人看到、提意见、一起改。

但新手最容易卡住的地方是：Git 和 GitHub 是两个东西。

对比GitGitHub
本质版本控制工具（一个装在电脑上的软件）托管 Git 仓库的网站（一个云服务）
谁做的Linus Torvalds（Linux 之父），2005 年2008 年上线，现属微软
装在哪你自己的电脑里浏览器 / 云端
断网能用吗能，本地照常提交不能
类比Word 的"修订模式 + 版本历史"存放文档的网盘 + 多人协作平台
◆
一句话记住

Git 负责"记录每一次改动"，GitHub 负责"把这些记录放到网上、并让别人也能参与"。所以你必须先装 Git，才能用 GitHub。

你用它来干什么

代码有备份，不怕丢BACKUP

笔记本坏了、误删了文件夹，代码还在 GitHub 上。换台电脑 git clone 一下就全回来。

后悔药，随便吃HISTORY

每一次提交都是一个存档点。改崩了能精确回到昨天下午那一版，还能看到当时改了哪几行。

作品集，求职时直接用PORTFOLIO

简历上写一个 github.com/你的名字，比说"我会写代码"有说服力得多。面试官真的会点开看。

参与开源，和人协作COLLAB

给别人的项目提改进、多人合作写一个项目、用 Issue 记待办，都在同一个地方完成。

✓
免费额度完全够用

个人账号可以创建无限个公有和私有仓库，没有数量限制。私有仓库只有你自己（和你邀请的人）能看。

!
别把 GitHub 当网盘

单个文件超过 100 MB 会被拒绝推送，超过 50 MB 会警告。视频、数据集、模型权重不要直接提交，用网盘或者 Git LFS。

02

注册账号与基础设置

10 分钟，一次做好，以后不用返工
1
打开 github.com，点右上角 Sign up

依次填：邮箱 → 密码（至少 15 位，或 8 位含数字和小写）→ 用户名 → 验证一下人类 → 收邮件填 6 位验证码。

2
认真想用户名

它会变成你的主页地址 github.com/用户名，并且会永久出现在你所有提交记录里，以后改起来很麻烦。

建议用「姓名拼音」或「拼音 + 专业关键词」：tangshengxiang、shengxiang-robotics、tsx-dev。避免 xiaoming2006、abc123 这类，将来写进简历会有点尴尬。

3
开启两步验证（2FA）——现在强制要求

注册完会引导你设置，也可以之后在 Settings → Password and authentication 里开。推荐用手机 App（Microsoft Authenticator / Google Authenticator / 1Password）扫二维码。

务必把恢复码（recovery codes）存下来，截图或打印。手机丢了又没有恢复码，账号基本找不回来。

4
完善个人主页

Settings → Public profile：传头像、写一句 bio（例如 "Robotics Engineering student @ CUG"）、填学校。

进阶技巧：新建一个和用户名同名的仓库，里面放一个 README.md，内容会自动显示在你的主页最上方，相当于个人简介页。

5
学生记得申请 Student Pack（重点）

访问 github.com/education → 用学校邮箱（*.edu.cn 一般可以）加学生证/录取通知书照片申请。通过后免费获得：GitHub Copilot Pro、GitHub Pro、以及一批云服务和开发工具的额度。

审核通常几天内出结果，越早申请越好。

✓
注册完的检查清单

① 头像换好 ② 2FA 已开启且恢复码已保存 ③ 用户名满意 ④ 邮箱已验证（Settings → Emails 里没有红字提醒）

安装并配置 Git

装一次，用四年

第一步：看看电脑里有没有

打开终端（Windows 用 Git Bash 或 PowerShell，macOS 用「终端」），输入：

bash
git --version

出现 git version 2.x.x 就说明已安装，可以跳到"配置"。提示找不到命令，就按下面的方法装。

Windows

  • 打开 git-scm.com/download/win，下载 64-bit Git for Windows Setup。
  • 安装时一路点 Next 即可，只有两处值得留意：
    · 默认编辑器：装了 VS Code 就选 Use Visual Studio Code，否则保持 Vim；
    · PATH 选项：保持默认的 Git from the command line and also from 3rd-party software。
  • 装完在开始菜单能搜到 Git Bash，用它敲命令最稳（Windows 的 PowerShell 也支持 git，但 Git Bash 更接近教程里的写法）。

macOS

bash
# 方式一：弹窗安装命令行工具（自带 git），推荐
xcode-select --install

# 方式二：用 Homebrew
brew install git

Linux（Ubuntu / Debian）

bash
sudo apt update
sudo apt install git -y

第二步：必做的全局配置

Git 需要知道"这次提交是谁做的"。名字和邮箱会写进每一条提交记录，所以要和 GitHub 账号保持一致。

bash
git config --global user.name "Tang Shengxiang"
git config --global user.email "你的邮箱@example.com"
git config --global init.defaultBranch main       # 新仓库默认分支叫 main
git config --global core.quotepath false          # 中文文件名不乱码
!
邮箱填哪个？

用你注册 GitHub 的邮箱最省事。如果不想公开真实邮箱，去 Settings → Emails 打开 Keep my email addresses private，它会给你一个 12345678+用户名@users.noreply.github.com 形式的地址，把上面第二条命令的邮箱换成它即可。

再补三条（可选但推荐）

bash · 按系统二选一
# Windows：自动处理换行符差异，避免满屏 LF/CRLF 警告
git config --global core.autocrlf true

# macOS / Linux：
git config --global core.autocrlf input

# 把默认编辑器换成 VS Code（提交说明会在这里编辑）
git config --global core.editor "code --wait"

检查是否配置成功

bash
git config --global --list
user.name=Tang Shengxiang
user.email=tangshengxiang@example.com
init.defaultbranch=main
...
◆
配置写在哪了？

--global 表示对当前用户的所有仓库生效，配置存在 ~/.gitconfig。去掉 --global 就只对当前仓库生效，存在仓库内的 .git/config。

04

4 个核心概念

理解了这张图，Git 就懂了一半

Git 的运作方式可以用一条"传送带"来理解。你的修改在四个地方之间流动，每一步对应一条命令：

工作区
你编辑的文件 ──git add──▶ 暂存区
待提交清单 ──git commit──▶ 本地仓库
.git 里的历史 ──git push──▶ GitHub
远程仓库
① 仓库 RepositoryREPO

一个被 Git 管理的文件夹。根目录下多了一个隐藏的 .git 目录，所有历史都存在里面。删了它，这个文件夹就变回普通文件夹。

② 提交 CommitCOMMIT

一次"存档"。包含一整份目录快照、说明文字、作者、时间，还有一个唯一编号（如 a3f9c21）。

③ 分支 BranchBRANCH

一条独立的时间线。默认叫 main。开新分支改代码，不影响主线，改好了再合并进去。

④ 远程 RemoteORIGIN

GitHub 上那份仓库的地址，通常命名为 origin。push 是推上去，pull 是拉下来。

换成写论文的场景

  • 工作区：你正在写的那份 Word。
  • git add：把这一稿放进"待归档"的文件夹。
  • git commit：封袋、写上"2026-10-23 完成第二章"，放进档案柜。袋子一旦封上就不再改动。
  • git push：把档案柜同步一份到云盘（GitHub）。
  • git pull：从云盘把别人更新过的档案柜同步回来。
◆
为什么要有"暂存区"这一步？

因为它允许你只提交一部分改动。比如你同时改了三个文件，但只想先提交其中两个 —— git add 那个两个，然后 commit。少了这一步就没有这种精细控制。

HEAD 是什么

终端里经常看到 HEAD -> main，意思是「你现在站在 main 分支的最新提交上」。它就是一个"你在这里"的指针。切换分支，HEAD 就跟着移过去。

05

创建第一个仓库

从这里开始，你的代码正式上线

路线 A：先在网上建空仓库，再克隆到本地（推荐新手）

1
新建仓库

登录 GitHub，点右上角的 + → New repository。

2
填写信息

· Repository name：hello-github（只能字母数字和 - _）
· Description：一句话说明，例如 "我的第一个 GitHub 仓库"
· Public / Private：作业和练手选 Private，想当作品集就选 Public
· Add a README file：一定要勾，否则是空仓库，克隆下来会提示"空仓库"
· Add .gitignore：按语言选，Python 项目就选 Python
· Choose a license：公开项目选 MIT

3
点 Create repository

仓库建好了。现在它存在于 GitHub 上，你的电脑上还没有副本。

4
克隆到本地

在仓库页面点绿色的 Code 按钮，复制地址，然后在你存放代码的目录里执行：

bash
# 先进入你想放代码的目录，例如桌面
cd ~/Desktop

git clone https://github.com/你的用户名/hello-github.git

cd hello-github
ls          # 应该能看到 README.md

到这一步，你已经完成了"云端 → 本地"。改个文件、提交、推回去，就是完整的一圈。

bash · 第一次推送
# 随便改一下 README.md，然后
git status
git add .
git commit -m "docs: 更新 README 说明"
git push
✓
恭喜，这就是全部核心操作了

剩下的所有内容，都是在这四条命令上加细节。刷新一下 GitHub 页面，你会看到刚才的修改和提交记录。

路线 B：本地已有代码，想传上去

比如你电脑上已经有个做好的课设文件夹，想把它放到 GitHub。

bash
# 1. 进入项目文件夹
cd ~/Desktop/我的机器人课设

# 2. 把它变成 Git 仓库
git init

# 3. 添加所有文件并提交
git add .
git commit -m "init: 项目初始化"

# 4. 确保分支名是 main（老版本 Git 默认是 master）
git branch -M main

# 5. 关联远程仓库（先在网页上建一个【不要勾 README】的空仓库）
git remote add origin https://github.com/你的用户名/仓库名.git

# 6. 推送，-u 表示记住这个默认远程，以后直接 git push 就行
git push -u origin main
!
最常见的翻车点

在网页新建仓库时勾了 README，本地 push 就会报 rejected ... fetch first —— 因为云端已经有一个提交，本地没有。解法见第 11 章，一句话：git pull --rebase origin main 之后再 push。

◆
git push -u origin main 里的 -u 是什么

它把本地 main 和远程 origin/main 绑定起来。只需要第一次带，之后直接 git push / git pull 即可，Git 知道该推到哪。

06

连接账号：配置 SSH 密钥

配一次，以后永远不用输密码

用 HTTPS 地址推代码时，GitHub 会要求你输入账号密码 —— 但从 2021 年起它已不接受密码，必须用 Personal Access Token，很麻烦。SSH 是更省事的选择：本机生成一对密钥，公钥交给 GitHub，之后所有操作自动认证。

1
检查有没有现成的密钥

如果 ~/.ssh/id_ed25519.pub 已经存在，可以跳过生成，直接用。

bash
ls -al ~/.ssh
2
生成密钥（ed25519 是目前推荐算法）
bash
ssh-keygen -t ed25519 -C "你的邮箱@example.com"

# 接下来连按三次回车即可：
Enter file in which to save the key (...):    ← 直接回车
Enter passphrase (empty for no passphrase):    ← 可以直接回车留空
Enter same passphrase again:               ← 再回车

会生成两个文件：id_ed25519（私钥，绝不外传）和 id_ed25519.pub（公钥，就是要交给 GitHub 的那个）。

3
复制公钥内容
bash · 三选一
# Windows (Git Bash)
clip < ~/.ssh/id_ed25519.pub

# macOS
pbcopy < ~/.ssh/id_ed25519.pub

# Linux
cat ~/.ssh/id_ed25519.pub   # 手动全选复制
4
粘贴到 GitHub

GitHub 右上头像 → Settings → 左侧 SSH and GPG keys → New SSH key → Title 随便写（如 "我的笔记本"）→ Key 框里粘贴 → Add SSH key。

5
测试连接
bash
ssh -T git@github.com

# 第一次会问是否信任 github.com，输入 yes 回车
Hi 你的用户名! You've successfully authenticated, but GitHub does not provide shell access.

看到 successfully authenticated 就成功了。

6
把已有仓库的地址换成 SSH

之前用 HTTPS 克隆的仓库，改成 SSH 地址，以后就不用 token 了：

bash
git remote -v                                # 先看现在的地址
git remote set-url origin git@github.com:你的用户名/仓库名.git
git remote -v                                # 确认已改成 git@ 开头
✕
私钥绝对不能泄露

id_ed25519（没有 .pub 后缀）等同于你的身份凭证。不要发微信、不要提交到仓库、不要贴到任何网站。万一泄露，立刻去 GitHub 删掉那把 key 并重新生成。

07

日常五步工作流

90% 的时间你只需要这五条命令
bash · 每天都会用
git pull                        # 1. 开工前，先拉取最新代码
# …改代码、写文件…
git status                      # 2. 看改了哪些文件
git add .                       # 3. 全部加入暂存区（或指定文件名）
git commit -m "feat: 添加电机控制模块"   # 4. 存档
git push                        # 5. 推送到 GitHub

逐条解释

git status —— 最该养成习惯的命令

它告诉你当前在哪条分支、哪些文件改了、哪些已经加入暂存区。红色是改了还没 add，绿色是已 add 待提交。拿不准状态时，先敲它。

输出示例
On branch main
Your branch is up to date with 'origin/main'.

Changes not staged for commit:
        modified:   src/main.py
Untracked files:
        new_file.txt

git add —— 选择要提交什么

命令作用
git add .提交当前目录下所有改动（最常用）
git add src/main.py只添加指定文件
git add src/添加整个目录
git add -A添加所有改动，包括删除操作
git add -p逐个代码块确认，精细到行（进阶）

git commit —— 写好说明很重要

说明文字是写给三个月后的自己看的。-m 后面直接跟内容，不加 -m 会打开编辑器让你写多行。

✕ 不要这样写

update · 修改 · aaa · 提交一下 · fix bug

✓ 推荐这样写

feat: 增加串口通信初始化 · fix: 修复 PID 参数溢出 · docs: 补充安装说明

常见的前缀（Conventional Commits 规范，用熟了就成习惯）：

前缀用于例子
feat新增功能feat: 支持多串口同时读取
fix修 bugfix: 解决舵机抖动问题
docs文档docs: 更新 README
refactor重构（不改功能）refactor: 拆分控制逻辑
chore杂活、依赖更新chore: 升级依赖版本

查看历史与差异

bash
git log --oneline --graph --all   # 图形化看所有提交
git log -5                          # 最近 5 条详情
git diff                           # 工作区 vs 暂存区（还没 add 的改动）
git diff --staged                  # 暂存区 vs 上次提交（即将提交的改动）
git show a3f9c21                   # 看某次提交改了什么
git log --author="Tang" --oneline  # 只看某人的提交

后悔药速查

我想……命令说明
丢弃某文件未提交的修改git restore 文件改动直接消失，无法恢复
取消暂存（add 错了）git restore --staged 文件改动还在，只是退回未暂存
改刚提交的说明git commit --amend -m "新说明"只能改最后一次，且没 push 过
撤销上次提交，保留代码git reset --soft HEAD~1改动回到暂存区，最安全
撤销上次提交，代码也不要git reset --hard HEAD~1危险，改动直接没了
撤销已经 push 的提交git revert <hash>生成一个反向提交，安全可追溯
✕
reset --hard 是唯一真会丢数据的命令

但也不是彻底没救：git reflog 会记录你每一次 HEAD 的移动，找到丢失前的那个 hash，再 git reset --hard <hash> 就能回来。只要没被 Git 清理（默认 30 天），任何提交都能救。

08

分支与 Pull Request

多人协作的标准姿势

为什么不能一直在 main 上改？因为 main 应该是随时可用的稳定版本。写新功能就开一条分支，改坏了不影响主线，改好了再合并回去。

常用分支命令

bash
git switch -c feature/login   # 新建并切换到 feature/login 分支
git branch                      # 查看本地所有分支（* 表示当前）
git branch -a                   # 连远程分支一起看
git switch main                 # 切回 main
git merge feature/login         # 在 main 上执行：把该分支合并进来
git branch -d feature/login     # 删除已合并的分支
◆
switch 还是 checkout？

Git 2.23 之后推荐用 git switch（切分支）和 git restore（恢复文件），语义更清楚。老教程里的 git checkout -b 分支名 和 git switch -c 分支名 完全等价，看到不用慌。

Pull Request 是什么

PR（简称）是"请求把我的分支合并进主线"的正式提案。在 GitHub 网页上发起，里面有代码差异对比、评论、审查、自动化检查，通过后点一下按钮完成合并。

1
在新分支上做出改动并推送
bash
git switch -c feature/login
# …写代码…
git add .
git commit -m "feat: 增加登录页面"
git push -u origin feature/login
2
在 GitHub 上发起 PR

推送完回到仓库页面，顶部会出现绿色条 Compare & pull request 按钮，点它。确认 base 是 main、compare 是你的分支，填标题和描述，点 Create pull request。

描述里写清三件事：改了什么、为什么改、怎么验证。这是个好习惯，将来团队里没人愿意猜。

3
合并

点 Merge pull request → Confirm merge。合并后有 Delete branch 按钮，删掉这个已完成的分支，保持清爽。

4
回到本地同步
bash
git switch main
git pull
git branch -d feature/login

三种合并方式怎么选

方式效果适合
Merge commit保留分支上所有提交，多一个合并节点多人项目，想完整保留开发过程
Squash and merge把分支上多次提交压成一条个人项目、提交比较碎时（推荐）
Rebase and merge提交一条条接到 main 上，历史成直线追求干净线性历史

遇到冲突怎么办

当两条分支改了同一个文件的同一片区域，Git 不知道听谁的，就停下来让你决定。文件里会出现这样的标记：

冲突标记
<<<<<<< HEAD
speed = 100          # 当前分支（main）的内容
=======
speed = 120          # 要合并进来的分支的内容
>>>>>>> feature/login

处理步骤：

  1. 打开文件，保留你要的那份（可以两者都留），把三行标记全部删掉。
  2. git add 文件名 告诉 Git 已解决。
  3. git commit 完成合并（Git 会给出默认说明，直接保存即可）。
bash
git status              # 看哪些文件冲突（both modified）
git add 冲突的文件
git commit
# 想放弃这次合并、回到合并前：
git merge --abort

参与开源：Fork 的用法

给别人的项目贡献代码

看到一个开源项目想改？你没有权限直接往人家仓库推代码。这时候用 Fork：在你自己账号下复制一份完整的项目，随便改，改好了向原项目发 PR。

操作含义结果在哪
Fork复制别人的仓库到你账号下你的 GitHub，github.com/你/原项目名
Clone把远程仓库下载到本地你的电脑
Branch在同一个仓库里开时间线仓库内部，不跨账号

完整流程

1
Fork

打开目标项目页面，点右上角 Fork → Create fork。几秒后你就有了一份自己的副本。

2
克隆自己的副本（注意是你的，不是原作者的）
bash
git clone git@github.com:你的用户名/项目名.git
cd 项目名
3
建分支、改代码、推送
bash
git switch -c fix/typo-in-readme
# …改…
git add .
git commit -m "fix: 修正 README 中的拼写错误"
git push -u origin fix/typo-in-readme
4
向原项目发起 PR

回到你 fork 的页面，会出现 Contribute 按钮 → Open pull request。确认箭头方向是「你的分支 → 原作者的 main」，写好说明，提交。

让 fork 跟上原项目的更新

原项目一直在更新，你的 fork 会越来越旧。加一个 upstream 指向原仓库，就能随时同步：

bash · 一次性配置
git remote add upstream https://github.com/原作者/项目名.git
git remote -v            # 应该看到 origin(你的) 和 upstream(原作者的)
bash · 每次同步
git fetch upstream
git switch main
git merge upstream/main
git push
✓
第一次贡献，找这些项目

在 GitHub 搜索框输入 label:"good first issue" language:python，或者在项目 Issues 里筛 good first issue / help wanted 标签。先从文档改错别字开始，是最容易被接受的第一个 PR。

◆
提 PR 的三个礼仪

① 先看 CONTRIBUTING.md 有没有规范；② 一个 PR 只做一件事，别把重构和修 bug 混在一起；③ 描述写清问题和验证方式。被拒绝也别介意，这是很正常的技术讨论。

一个像样的仓库需要什么

从"能跑"到"别人愿意看"

README.md —— 项目的门面

打开任何仓库，页面下方显示的就是 README。它是别人判断"这个项目值不值得看"的唯一依据。直接用这个模板，把括号内容换掉：

markdown
# 项目名称

一句话说明这个项目是干什么的。

## 功能
- 功能 1
- 功能 2

## 环境要求
- Python 3.10+
- 依赖：见 requirements.txt

## 安装
```bash
git clone https://github.com/你的用户名/项目名.git
cd 项目名
pip install -r requirements.txt
```

## 使用方法
```bash
python main.py
```

## 项目结构
```
├── src/          源码
├── tests/        测试
└── README.md
```

## 作者
唐晟翔 · 中国地质大学（武汉）
✓
README 的三个必备信息

是什么（一句话）、怎么跑（能复制的命令）、长什么样（截图或动图）。有截图的项目，star 数通常高一个数量级。

.gitignore —— 别把垃圾提交上去

有些文件不该进仓库：编译产物、依赖包、密钥、日志、数据集。写进 .gitignore，Git 就会自动忽略它们。

.gitignore · Python 项目示例
# Python
__pycache__/
*.py[cod]
*.egg-info/
.venv/
venv/
env/

# 环境变量与密钥（重要！）
.env
*.key
*.pem
config.local.*

# 编辑器
.vscode/
.idea/

# 系统文件
.DS_Store
Thumbs.db

# 数据与产物
*.log
data/
output/
node_modules/
!
已经提交过的文件，加进 .gitignore 不会自动消失

需要先从 Git 里移除（本地文件保留）：git rm --cached 文件名，再提交。如果是整个目录：git rm -r --cached 目录名。

LICENSE —— 别人能不能用你的代码

许可证别人可以常见于
MIT随便用、改、商用，只需保留版权声明最流行，个人项目首选
Apache 2.0同上，另加专利授权条款企业级项目
GPL 3.0可以用，但衍生作品也必须开源强调开源的软件
无 LICENSE法律上默认保留所有权利，别人不能合法使用想开源就别这样

推荐的仓库结构

text
项目名/
├── README.md          # 门面，必须有
├── LICENSE            # 开源协议
├── .gitignore         # 忽略规则
├── requirements.txt   # 依赖清单
├── src/               # 源码
├── tests/             # 测试
├── docs/              # 文档、图片
└── .github/
    └── workflows/     # CI 自动化配置

报错急救手册

新手 90% 的报错都在这一页
报错关键词原因解法
not a git repository当前目录不是仓库cd 到仓库目录，或 git init
Permission denied (publickey)SSH 密钥没配好见下方详解
rejected ... fetch first远程有你本地没有的提交git pull --rebase 后再 push
Please tell me who you are没配 user.name / user.email回到第 3 章配一遍
remote origin already exists已经关联过远程git remote set-url origin 新地址
refusing to merge unrelated histories两边历史完全无关git pull --allow-unrelated-histories
LF will be replaced by CRLFWindows 换行符警告，不影响配置 core.autocrlf，可忽略
file size limit exceeded单文件超过 100 MB用 Git LFS，或不提交该文件
Could not resolve host网络 / DNS / 代理问题检查网络，或配代理
git: command not foundGit 没装或没进 PATH重装 Git，重开终端

详解：Permission denied (publickey)

说明 GitHub 不认你的钥匙。按顺序排查：

bash
# 1. 测试连接，看具体原因
ssh -T git@github.com

# 2. 看本机有哪些 key，ssh 是否在用它们
ssh-add -l
ls -al ~/.ssh

# 3. 如果 key 存在但没被加载
ssh-add ~/.ssh/id_ed25519

# 4. 确认公钥已贴到 GitHub
cat ~/.ssh/id_ed25519.pub
# 打开 github.com/settings/keys 对比是否一致

# 5. 确认仓库地址是 SSH 形式
git remote -v      # 应为 git@github.com:用户名/仓库.git

详解：推送被拒（non-fast-forward）

bash
# 标准解法：先把远程的东西拉下来，变基到它后面，再推
git pull --rebase origin main
git push

# 如果 rebase 过程报冲突：改好文件 → git add . → git rebase --continue
# 想放弃这次 rebase：git rebase --abort
✕
不要用 git push -f 解决这个报错

强制推送会覆盖远程历史，如果别人也在这个仓库上工作，他们的提交会被直接抹掉。只有确定这个仓库只有你一个人、且清楚自己在做什么时才用。

详解：不小心提交了密钥

  1. 立刻去源头废除它：如果是 API Key，到对应平台重新生成；如果是 SSH 私钥，到 GitHub 删除该 key。
  2. 从仓库历史里清除（普通删除提交还不够，历史里仍可查到）。推荐用 git filter-repo 工具，或直接删掉整个仓库重建。
  3. 把该文件加进 .gitignore，以后不再提交。

更根本的做法：密钥永远放 .env，.env 永远在 .gitignore 里。

四周学习路径

第 1 周 · 跑通一次基础

装好 Git → 配 SSH → 建 hello 仓库 → 完成 clone / add / commit / push 一圈。目标：不再害怕命令行。

第 2 周 · 当成日常工具习惯

把正在写的课设、算法题、笔记都放进仓库。每天至少提交一次，写好 commit message。

第 3 周 · 分支与 PR协作

练习开分支改功能、自己给自己发 PR、故意制造一次冲突并解决它。学会 git log --graph 看懂历史。

第 4 周 · 贡献与自动化进阶

给开源项目提一个小 PR；用 GitHub Pages 部署个人主页；用 GitHub Actions 跑一次自动测试。

接下来可以学什么

  • GitHub Pages：把仓库变成网站，免费托管个人主页（仓库 Settings → Pages）。
  • GitHub Actions：提交代码后自动跑测试、自动部署，写在 .github/workflows/ 里。
  • Issues + Projects：用看板管理待办，比记在备忘录里强。
  • Releases：给项目打版本号，附上可执行文件供别人下载。
  • gh CLI：在终端里直接建 PR、看 issue，不用开浏览器。
  • VS Code 集成：侧边栏的源代码管理面板能点按钮完成 add / commit / push，适合不熟命令时过渡。

常见疑问 FAQ

新手最常问的几件事
必须用命令行吗？可以用图形界面吗？

不必。有三个选择：① 命令行，最通用，教程和文档都这么写；② VS Code 源代码管理面板，点点鼠标就能提交推送，适合过渡；③ GitHub Desktop，官方客户端，最简单。

但建议至少会用 clone / add / commit / push / pull 五条 —— 遇到问题时，报错信息只有命令行会给全，图形界面往往只弹一句"操作失败"。

私有仓库别人能看到吗？老师/同学能找到吗？

看不到。私有仓库只有你自己和被你邀请的协作者能访问，不会出现在搜索里，主页也不显示。免费账号可以建无限个私有仓库。

但注意：如果仓库是 Public，历史里删掉的东西也能被翻出来。上传前先检查有没有密码、密钥、身份证照片。

我提交了错误的邮箱/名字，能改吗？

能，但改了会重写历史（Hash 全变）。如果仓库只有你一个人，用：

git commit --amend --author="新名字 <新邮箱>" 只改最后一次。

批量改历史推荐 git filter-repo 工具，或者干脆删了仓库重新上传——对个人项目来说后者更快。

能把 Word、PPT、视频传上去吗？

技术上可以，但不推荐。Git 擅长比对文本差异，对二进制文件每次修改都是存一整份新副本，仓库会迅速膨胀到几百 MB。

确实需要版本管理的二进制文件（如大模型权重、数据集）用 Git LFS；纯备份的话用网盘就行。

中文文件名显示成一串数字和字母？

执行 git config --global core.quotepath false，之后 git status 就能正常显示中文了。这只影响显示，不影响文件本身。

怎么删除一个仓库？

进入仓库 → Settings → 滚到最下面 Danger Zone → Delete this repository → 输入仓库全名确认。

删除后不可恢复，本地副本还在（.git 目录仍然完整），先确认真的不要了。

clone 特别慢或者一直失败怎么办？

通常是网络问题。可尝试：① 换网络环境；② 用 SSH 而不是 HTTPS；③ 只克隆最近的历史：git clone --depth 1 地址（体积能小很多，适合只想看代码的情况）。

已经 push 了，还能改那次提交吗？

最好不要改历史，用 git revert <hash> 生成一个"反做"的新提交，安全且痕迹清晰。

如果确实要改（个人项目），改完需要 git push --force-with-lease。注意这个操作会覆盖远程，团队协作时是禁忌。

最后：今天就做完这五件事

  1. 注册 GitHub，开好 2FA 并保存恢复码。
  2. 装好 Git，配好 user.name 和 user.email。
  3. 配好 SSH 密钥，ssh -T git@github.com 看到成功提示。
  4. 建一个 hello-github 仓库，克隆下来，改 README，push 回去。
  5. 把手机里那份"总有一天要用"的代码，放进第二个仓库。

做完这五步，你已经超过大多数"想学 GitHub 但一直没开始"的人了。剩下的只是重复。
